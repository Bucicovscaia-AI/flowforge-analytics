# Data validation and cleaning rules

FlowForge never changes the uploaded file. It reads every cell as text, checks
the file, describes it as received (the *profile*), then applies the cleaning
rules below **in order** and records how many rows or cells each rule changed.
Every KPI is calculated from the cleaned rows only.

Source: `backend/app/services/csv_loader.py` (validation) and
`backend/app/services/cleaning.py` (profile and rules C1–C8).

## 1. File validation (the upload is rejected if any check fails)

| Check | Rule | HTTP status |
| --- | --- | --- |
| Extension | File name must end in `.csv` (any case) | 415 |
| Content type | Must be a CSV-like type (`text/csv`, `text/plain`, `application/vnd.ms-excel`, …); e.g. `application/pdf` is refused | 415 |
| Binary content | A NUL byte in the first 8 KB (e.g. an `.xlsx` renamed to `.csv`) is refused | 415 |
| Empty file | 0 bytes, or only whitespace | 400 |
| Size | Larger than `MAX_UPLOAD_MB` (default 5 MB). Checked from `Content-Length` before the body is read, and again on the bytes received | 413 |
| Encoding | UTF-8 (with or without BOM), then Windows-1252; anything else is refused | 422 |
| Delimiter | Comma, semicolon or tab (detected automatically) | – |
| Row shape | Every row must have the same number of fields as the header; unclosed quotes are refused. The line number is reported | 422 |
| Limits | At most `MAX_ROWS` (100,000) rows and `MAX_COLUMNS` (50) columns | 413 / 422 |
| Header | No blank or duplicated column names | 422 |
| Required columns | `order_id`, `order_date`, `quantity`, `unit_price` must exist. All missing ones are listed | 422 |

Header names are normalised (`Order Date ` → `order_date`) and common
alternatives are mapped: `Qty` → `quantity`, `Price` → `unit_price`,
`Date`/`Transaction Date` → `order_date`, `Category` → `product_category`,
`Segment` → `customer_type`, and so on (`COLUMN_ALIASES`).

The CSV is parsed with Python's `csv` module in strict mode rather than
`pandas.read_csv`, because pandas silently shifts or drops cells when a row
has too many fields.

## 2. Inspection (profile of the file as received)

For every column: inferred type, role (required, optional or extra), missing
count and percentage, invalid count (dates that cannot be read, quantities
that are not whole numbers above zero, prices that are not numbers or are
negative), distinct values and three example values. For the dataset: rows,
columns, exact duplicate rows, missing cells and completeness.

A cell counts as **missing** if it is empty or one of: `NA`, `N/A`, `nan`,
`null`, `none`, `-`, `--`, `?` (case-insensitive).

## 3. Cleaning rules

| Rule | What it does | Why |
| --- | --- | --- |
| C1 | Trim spaces from every cell; turn placeholder text into a real missing value | `" Lamp "` and `"Lamp"` are the same product; `"N/A"` is not a channel |
| C2 | Remove exact duplicate rows, keeping the first copy | A row exported twice would double-count revenue |
| C3 | Remove rows missing `order_id`, `order_date`, `quantity` or `unit_price` | Revenue and order counts cannot be calculated without them |
| C4 | Parse `order_date` (ISO `yyyy-mm-dd`, then UK `dd/mm/yyyy`); remove rows whose date cannot be read or does not exist (e.g. 30 February) | Monthly figures need a real date |
| C5 | Parse `quantity`; remove rows where it is not a whole number above zero | Negative quantities are usually returns, which this analysis does not model |
| C6 | Parse `unit_price` (strips `£ $ €` and thousands separators); remove rows where it is not a number or is negative | `£1,250.00` is a valid price; `abc` is not |
| C7 | Make category spellings consistent in `product_category`, `region`, `channel`, `customer_type`, using the most common spelling of each value | `north` and `North` are one region |
| C8 | Fill missing values in optional text columns with `Unknown` | Keeps the row (its revenue is valid) while showing the gap |

After cleaning, `revenue = quantity × unit_price` is added to each row.

**Data quality score** = rows kept after cleaning ÷ rows received × 100.

## 5. What is not handled

* Returns, refunds, discounts, tax and shipping are not modelled.
* Duplicate *orders* with different content (e.g. the same `order_id` with a
  different date) are kept: an order can legitimately have several lines.
* Currencies are not converted; all prices are treated as GBP.
